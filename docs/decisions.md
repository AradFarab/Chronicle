# تصمیم‌های پروژه نرم‌افزار حضور و غیاب

همه تصمیم‌ها با آراد در ۱۴ مهر ۱۴۰۵ گرفته شده‌اند. سند کامل طراحی: `docs/design-doc.md`.

## استقلال از Frappe (تصمیم آراد، ۱۵ مهر ۱۴۰۵)

دلیل: Frappe بستر برنامه‌های دیگر هم هست و برای ما سنگین است (نصب، Desk، وابستگی به نسخه‌ها).

| موضوع | تصمیم |
| --- | --- |
| معماری | بک‌اند مستقل پایتون (FastAPI) روی PostgreSQL؛ بدون Frappe، Redis و MariaDB |
| دیتابیس | PostgreSQL با طرح تمیز و مستند (`docs/data-model.md`)؛ هر تغییر با مهاجرت Alembic؛ قیدها داخل خود دیتابیس |
| تاریخ | همچنان شمسی؛ نوع `jdate` در دیتابیس با بررسی شکل `1405/07/14`. جدول «روز تقویم» حذف می‌شود؛ روز هفته از jdatetime و تعطیلی از جدول تعطیلات |
| تقویم و تعطیلات | منبع رسمی time.ir؛ اپراتور آخر هر سال (یا هر وقت لازم شد) «به‌روزرسانی تقویم» را برای سال بعد می‌زند، پیش‌نمایش تغییرات را می‌بیند و تأیید می‌کند. داده آفلاین داخل برنامه برای وقتی که اینترنت نیست، با برچسب «پیش‌بینی». ورود فایل هم ممکن است |
| کتابخانه‌ها | jdatetime برای محاسبه تاریخ؛ کتابخانه rokh بررسی شد ولی تاریخ قمری را با تقویم عربستان (ام‌القری) حساب می‌کند که با تقویم رسمی ایران گاهی یک روز فرق دارد، پس منبع تعطیلات نیست |
| رابط کاربری | همه صفحه‌ها، از جمله تعریف کاربر، پرسنل، شیفت، الگو و تنظیمات، داخل همان PWA |
| حفظ می‌شود | موتور قانون کار، تقویم شمسی، آداپتور دستگاه، خروجی‌ها، PWA و همه قواعد CLAUDE.md |
| ترتیب کار | ۱) دیتابیس PostgreSQL ۲) تقویم ۳) فرم‌ها و فرایندها (درخواست و تأیید) ۴) بقیه |

### جزئیات فنی پیاده‌سازی (۱۵ مهر ۱۴۰۵)

| موضوع | تصمیم |
| --- | --- |
| کارهای پس‌زمینه | فرایند جدا `hozur worker`: هر چند ثانیه دستگاه‌هایی که وقت خواندنشان رسیده را می‌خواند، صف کارها (جدول `job`) را اجرا می‌کند و هر شب محاسبه دیروز و امروز، تخصیص مرخصی ماه قبل و بستن سال مرخصی را انجام می‌دهد. همه این کارها تکرارپذیرند، پس اگر سرور یک شب خاموش باشد شب بعد جبران می‌شود |
| محاسبه دوباره | هر تغییر (تردد جدید، تأیید درخواست، تعطیلی، شیفت، الگو، قواعد) یک کار «محاسبه دوباره» در صف می‌گذارد؛ ماه‌های بسته و روزهای آینده هرگز محاسبه نمی‌شوند؛ تغییر تنظیمات حداکثر یک سال به عقب را دوباره حساب می‌کند |
| هشدار غیبت | جدول اعلان جدا ندارد؛ فهرست کسانی که چند روز کاری پشت سر هم غیبت دارند هنگام نمایش از روی کارکرد روزانه حساب می‌شود (فقط هشدار، ماده ۲۷) |
| بستن ماه | فقط وقتی ماه تمام شده، درخواست در انتظار ندارد و محاسبه‌ای در صف نیست؛ بازکردن با دلیل و ثبت در تاریخچه |
| رمز ارتباطی دستگاه | رمزنگاری‌شده با کلید برگرفته از `HOZUR_SECRET_KEY`؛ در پاسخ API و تاریخچه تغییرات نمی‌آید |
| صفحه‌های تنظیمات | جدول‌های ساده (شعبه، واحد، سمت، پرسنل، شیفت، الگو، انتساب، قواعد، انواع مرخصی، فرایند تأیید) با یک توصیف واحد در سرور و PWA ساخته می‌شوند؛ تقویم، دوره‌ها، کاربران، دستگاه‌ها و گزارش‌ها صفحه اختصاصی دارند |
| نشانی برنامه | PWA در ریشه سایت (`/`) و API زیر `/api`؛ ورود با صفحه ورود خود برنامه |
| استقرار | یک ایمیج Docker برای وب و worker، به‌همراه PostgreSQL 17 در `docker/compose.yml` روی سرور خود شرکت |

## تغییر ساختار سازمان (تصمیم آراد، ۱۷ مهر ۱۴۰۵)

| موضوع | تصمیم |
| --- | --- |
| اپراتور | اپراتور و مدیر سیستم یکی هستند؛ فقط نقش «مدیر سیستم» (admin) وجود دارد. مدیرعامل و مدیر نقش جدا نیستند و از روی سمت‌ها مشخص می‌شوند |
| کارمند = کاربر | هر کارمند یک کاربر هم هست. هنگام تعریف کارمند، نام کاربری (پیش‌فرض: کد پرسنلی) و رمز عبور هم ثبت می‌شود. کارمند ترک‌کار یا معلق وارد برنامه نمی‌شود |
| کد تفصیلی | فیلد جدید «کد تفصیلی» برای هر کارمند (یکتا، اختیاری) |
| واحد | واحد فقط یک برچسب ساده است که به افراد می‌خورد تا گزارش‌گیری آسان شود؛ سلسله‌مراتب، مدیر و جانشین ندارد. هر نفر یک واحد |
| سمت | سمت‌ها جدا تعریف می‌شوند و درخت (زیرشاخه) دارند. هر سمت می‌تواند چند نفر داشته باشد و هر نفر چند سمت. سمت را می‌شود به فرد داد و از او گرفت (تاریخ شروع و پایان؛ سابقه می‌ماند). سمتِ «مدیرعامل» بالای درخت است |
| پرنت | پرنت هر نفر کسانی‌اند که نزدیک‌ترین سمتِ پرشدهٔ بالای سمت او را دارند. اگر سمت بالا خالی باشد، یک سطح بالاتر. مدیرعامل پرنت ندارد |
| سه فرایند تأیید | ۱) پرنت تأیید می‌کند. ۲) پرنت و بعد مدیرعامل (اگر پرنت خودِ مدیرعامل باشد فقط تأیید او). ۳) مستقیم مدیرعامل. درخواست خودِ مدیرعامل تأیید نمی‌خواهد. هر کدام از دارندگان سمتِ پرنت می‌توانند تأیید کنند |
| واگذاری تأیید | هر کس که زیردست دارد می‌تواند اختیار تأییدش را برای بازه‌ای به شخص دیگر واگذار کند؛ هم او و هم نماینده می‌توانند تأیید کنند و سابقه نشان می‌دهد چه کسی تأیید کرده |
| محل کار | «شعبه» حذف و به «محل کار» (مکان فیزیکی کار) تبدیل شد؛ استان محل کار تعطیلات استانی را مشخص می‌کند |
| ورود اکسلی | برای هر جایی که کاربر می‌تواند مورد جدید تعریف کند، نمونهٔ اکسل با همهٔ فیلدها و قالب‌ها (متن برای تاریخ و ساعت، لیست‌های کشویی) دانلود می‌شود و فایل پرشده با همان اعتبارسنجی فرم وارد می‌شود. ورود «همه یا هیچ» است و ردیف‌های اشتباه با شمارهٔ ردیف گزارش می‌شوند |
| شیفتِ شبانه | شیفت ۱۸ تا ۶ صبح روز بعد درست حساب می‌شود (ورود و خروج به روزِ شروع شیفت تعلق دارد؛ شب‌کاری ۲۲ تا ۶ جدا حساب می‌شود) و با آزمون پوشش داده شده است |
| چرخش دو هفته‌ای | الگوی «چرخشی» با چرخهٔ ۲۸ روزه (۱۴ روز صبح، ۱۴ روز شب) پشتیبانی می‌شود. برای اینکه دو گروه نگهبان یکی صبح و دیگری شب شروع کنند، هر انتساب «شروع از روزِ چندم چرخه» (`cycle_offset_days`) دارد |
| بیمه‌ای‌ها | ساخته نشد. درخواست «افرادی که فقط برایشان بیمه رد می‌شود و در گزارش معلوم نباشد کار نمی‌کنند» یعنی نشان‌دادن کار برای کسی که کار نمی‌کند؛ این در گزارش‌های حضور و بیمه جعل سابقه است و ساخته نمی‌شود. اگر نیاز واقعی چیز دیگری است (مثلاً فهرست بیمه جدا از حضور و غیاب) باید توضیح داده شود |

## سؤال باز

- ۲۵ فروردین ۱۴۰۵ (شهادت امام صادق): داده رسمی ماه‌های قمری (۱ شوال ۱۴۴۷ = ۱ فروردین ۱۴۰۵) آن را تعطیل نشان می‌دهد، ولی در فهرست ۲۵ روزه فایل قوانین نیست. فعلاً طبق فایل وارد نشده است.
